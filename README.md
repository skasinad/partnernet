# Partnernet

Partnership matchmaking for independent businesses. Partnernet ranks other
small businesses by how much they share your customer base — audience overlap,
complementary industry, and proximity — then lets you send partnership
requests and message confirmed partners.

- **Backend** — Django 5 + Django REST Framework, JWT auth, PostgreSQL. Deploys to Render.
- **Frontend** — Next.js 15 (App Router) + TypeScript + Tailwind. Deploys to Vercel.

```
partnernet/
├── backend/     Django REST API
└── frontend/    Next.js app
```

## What's in it

| Area | Details |
| --- | --- |
| Accounts | Email + password, JWT access/refresh with transparent refresh-and-retry |
| Business profile | Category, audience tags (age / interest / price / lifestyle), price tier, size, location (city + optional coordinates), links, partnership pitch |
| Matching | Transparent 0–100 score: 55% audience (tag Jaccard + price-tier bonus), 25% industry (same or curated adjacency), 20% proximity (haversine when coordinates exist, else city/region tiers) |
| Discovery | Public browse with search + category / price / city / audience filters, pagination |
| Partnership requests | Send / accept / decline / withdraw, incoming + outgoing inboxes, summary counts |
| Messaging | 1:1 threads unlocked only between confirmed partners, unread tracking, 6s polling |
| Public profiles | `/business/<slug>` renders for logged-out visitors |

## Local development

### 1. Backend

```bash
cd backend
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed          # demo data — 24 businesses, requests, a conversation
python manage.py runserver 8000
```

Demo logins: any `<name>@demo.partnernet.app` (e.g. `rowanbean@demo.partnernet.app`)
with password `partnernet-demo`. Create a superuser with
`python manage.py createsuperuser` for the Django admin at `/admin/`.

### 2. Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local   # NEXT_PUBLIC_API_URL=http://localhost:8000
npm run dev                         # http://localhost:3000
```

### Tests

```bash
cd backend && python manage.py test
```

## Deployment

### Backend → Render

The repo includes `backend/render.yaml` (a Blueprint) and `backend/build.sh`.

1. Push this repo to GitHub.
2. In Render, **New → Blueprint**, point it at the repo. It creates a free
   Postgres instance and a web service (`rootDir: backend`).
3. After the first deploy, set two env vars on the web service to your Vercel URL:
   - `DJANGO_CORS_ALLOWED_ORIGINS` = `https://your-app.vercel.app`
   - `DJANGO_CSRF_TRUSTED_ORIGINS` = `https://your-app.vercel.app`
4. Open a shell on the service and run `python manage.py seed` if you want demo data.

`DJANGO_SECRET_KEY` is generated by Render; `DATABASE_URL` is wired from the
database automatically. `*.vercel.app` preview URLs are already allowed via a
CORS regex.

### Frontend → Vercel

1. In Vercel, **Add New → Project**, import the repo.
2. Set **Root Directory** to `frontend`.
3. Add env var `NEXT_PUBLIC_API_URL` = `https://your-api.onrender.com` (no trailing slash).
4. Deploy. Framework preset, build command, and output are auto-detected.

## Matching model

`backend/businesses/matching.py` is pure functions — `score_pair(a, b)` returns a
`MatchBreakdown` with the total, the three component scores, the shared audience
tags, and a plain-English reason. Curated industry adjacencies (cafe ↔ bookshop,
gym ↔ juice bar, florist ↔ photographer, …) live in `ADJACENT_CATEGORIES`.
